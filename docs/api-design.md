# API設計書

## 1. 基本方針

* API形式：REST API
* データ形式：JSON
* バックエンド：FastAPI
* 認証方式：JWT認証
* APIのベースURL：`/api/v1`
* 日時形式：ISO 8601形式
* 文字コード：UTF-8

---

# 2. 認証API

## 2.1 ユーザー新規登録

### 概要

メールアドレスとパスワードを受け取り、新しいユーザーを登録する。

### エンドポイント

```http
POST /api/v1/auth/register
```

### 認証

不要

### リクエストボディ

```json
{
  "email": "test@example.com",
  "password": "password123"
}
```

### リクエスト項目

| 項目       | データ型   | 必須 | 説明             |
| -------- | ------ | -: | -------------- |
| email    | string | 必須 | ユーザーのメールアドレス   |
| password | string | 必須 | ログインに使用するパスワード |

### 入力条件

* メールアドレスの形式が正しいこと
* メールアドレスが未登録であること
* パスワードは8文字以上であること
* パスワードはデータベースに平文で保存しない
* パスワードをハッシュ化し、`password_hash`として保存する

### 成功レスポンス

ステータスコード：

```http
201 Created
```

レスポンスボディ：

```json
{
  "id": 1,
  "email": "test@example.com",
  "message": "ユーザー登録が完了しました"
}
```

### エラーレスポンス

#### メールアドレスの形式が不正

```http
422 Unprocessable Entity
```

```json
{
  "detail": "メールアドレスの形式が正しくありません"
}
```

#### パスワードが8文字未満

```http
422 Unprocessable Entity
```

```json
{
  "detail": "パスワードは8文字以上で入力してください"
}
```

#### メールアドレスが登録済み

```http
409 Conflict
```

```json
{
  "detail": "このメールアドレスはすでに登録されています"
}
```

## 2.2 ログイン

### 概要

メールアドレスとパスワードを照合し、認証に成功した場合はアクセストークンを返す。

### エンドポイント

```http
POST /api/v1/auth/login
```

### 認証

不要

### リクエストボディ

```json
{
  "email": "test@example.com",
  "password": "password123"
}
```

### リクエスト項目

| 項目       | データ型   | 必須 | 説明            |
| -------- | ------ | -: | ------------- |
| email    | string | 必須 | 登録済みのメールアドレス  |
| password | string | 必須 | 登録時に設定したパスワード |

### 成功レスポンス

ステータスコード：

```http
200 OK
```

レスポンスボディ：

```json
{
  "access_token": "xxxxxxxxxxxxxxxx",
  "token_type": "bearer"
}
```

### エラーレスポンス

#### メールアドレスまたはパスワードが不正

```http
401 Unauthorized
```

```json
{
  "detail": "メールアドレスまたはパスワードが正しくありません"
}
```

### 補足

セキュリティ上、メールアドレスとパスワードのどちらが間違っているかは区別して返さない。

---

## 2.3 ログイン中のユーザー情報取得

### 概要

アクセストークンからログイン中のユーザーを特定し、ユーザー情報を返す。

### エンドポイント

```http
GET /api/v1/users/me
```

### 認証

必要

HTTPヘッダーにアクセストークンを設定する。

```http
Authorization: Bearer xxxxxxxxxxxxxxxx
```

### リクエストボディ

なし

### 成功レスポンス

ステータスコード：

```http
200 OK
```

レスポンスボディ：

```json
{
  "id": 1,
  "email": "test@example.com",
  "created_at": "2026-07-24T18:00:00+09:00"
}
```

### エラーレスポンス

#### トークンが設定されていない

```http
401 Unauthorized
```

```json
{
  "detail": "認証情報が必要です"
}
```

#### トークンが不正または期限切れ

```http
401 Unauthorized
```

```json
{
  "detail": "認証情報が無効です"
}
```

## 2.4 ログアウト

### 概要

アプリ側に保存されているアクセストークンを削除し、ログイン状態を終了する。

### エンドポイント

Ver1ではログアウト専用APIを作成しない。

### 処理内容

Flutter側で保存しているアクセストークンを削除する。

```text
アクセストークンを端末から削除
↓
認証が必要な画面へアクセスできなくなる
↓
ログイン画面へ移動
```

### 補足

JWTはサーバーがログイン状態を保持しない方式であるため、Ver1ではサーバーへのログアウト要求を行わない。

将来的に以下を導入する場合は、ログアウトAPIを追加する。

* リフレッシュトークン
* トークン失効リスト
* 複数端末のログイン管理
* 全端末からのログアウト

# 3. 認証の流れ

## 3.1 新規登録

```text
Flutter
  ↓ メールアドレス・パスワード
POST /api/v1/auth/register
  ↓
FastAPI
  ↓ 入力内容を検証
  ↓ パスワードをハッシュ化
  ↓ usersテーブルに保存
  ↓
登録結果をFlutterへ返す
```

## 3.2 ログイン

```text
Flutter
  ↓ メールアドレス・パスワード
POST /api/v1/auth/login
  ↓
FastAPI
  ↓ usersテーブルからユーザーを検索
  ↓ パスワードを照合
  ↓ JWTアクセストークンを発行
  ↓
Flutterがアクセストークンを保存
```

## 3.3 認証が必要なAPIへのアクセス

```text
Flutter
  ↓ Authorizationヘッダーにトークンを設定
GET /api/v1/users/me
  ↓
FastAPI
  ↓ トークンを検証
  ↓ ユーザーを特定
  ↓
ユーザー情報をFlutterへ返す
```

# 4. 認証API一覧

| HTTPメソッド | エンドポイント                 | 機能             | 認証 |
| -------- | ----------------------- | -------------- | -- |
| POST     | `/api/v1/auth/register` | ユーザー新規登録       | 不要 |
| POST     | `/api/v1/auth/login`    | ログイン           | 不要 |
| GET      | `/api/v1/users/me`      | ログイン中のユーザー情報取得 | 必要 |
